프로젝트 분석 시스템 · 프로토타입 v0.6
======================================

프로젝트 폴더를 불러와 [Run]을 누르면, 어떤 시스템인지와
DB 테이블·메뉴·화면·배치의 관계를 정리해 보여 줍니다.
분석은 이 PC 안에서만 하고 인터넷이 없어도 됩니다.
데스크톱 앱에서 AI 연동(Claude·Gemini·ChatGPT), 형상관리(Git·SVN)·작업 이력, DB 연결을 쓸 수 있습니다.
버전별로 바뀐 내용은 CHANGELOG.md(저장소)에 있습니다. 지금 버전은 앱 상단 이름 옆에 보입니다.


1. 실행 방법
-------------
[데스크톱 앱]
  1) ProjectAnalyzer-…-win.zip 압축을 풉니다. (설치 필요 없음, 관리자 권한 필요 없음)
  2) 폴더 안의 ProjectAnalyzer.exe 를 실행합니다.
  3) 처음 실행할 때 "Windows의 PC 보호" 창이 뜨면 [추가 정보] → [실행]을 누릅니다.
     (코드 서명을 하지 않은 프로토타입이라 나오는 안내입니다)

[HTML 파일]
  1) project-analyzer.html 을 Edge 또는 Chrome으로 엽니다.
  2) 폴더를 고르면 브라우저가 "파일을 업로드할까요?"라고 묻습니다.
     실제로 업로드되지 않고, 이 브라우저 안에서만 읽습니다. [업로드]를 누르면 됩니다.
  * AI 연동·형상관리·DB 연결은 데스크톱 앱에서만 됩니다.

[소스에서 실행 (GitHub)]
  Node.js 22 LTS를 설치한 뒤, 저장소 폴더(project_management)에서:
    npm start          ← 패키지 설치(처음이거나 바뀌었을 때만, 처음엔 몇 분) → 빌드 → 실행
    npm run package    ← 실행 파일 zip 만들기 (release\ProjectAnalyzer-…-win.zip, 몇 분 걸림)
  * 새 코드를 받을 때: git pull 뒤 npm start
    앱을 켜 둔 채 실행하면 열린 앱이 새 버전으로 [다시 시작]할지 묻습니다.
    npx electron . 은 다시 빌드하지 않으므로 새 코드가 반영되지 않습니다(경고가 뜸).
  * desktop 폴더 안에서 npm start 를 해도 됩니다. node scripts\… 명령은 저장소 폴더에서 실행해야 합니다.


2. 분석 사용 순서
------------------
  1) [폴더 열기]를 누르거나 프로젝트 폴더를 창에 끌어다 놓습니다.
  2) 불러오기 확인 화면에서 분석에서 뺄 폴더를 체크 해제하고 [분석 시작]을 누릅니다.
  3) 결과 요약에서 시스템 유형, 사용 언어·DB, 개수, 확인 필요 항목을 봅니다.
  4) 왼쪽 트리(DB 테이블 / 메뉴 / 화면 / 배치)에서 항목을 누르면 상세가 나옵니다.
  5) 파일 이름을 누르면 소스 보기가 열리고, 근거가 된 줄을 강조해 보여 줍니다.
  6) [결과 파일 저장]으로 결과를 .json 파일로 남길 수 있습니다. (소스 코드는 담지 않습니다)
  * 분석한 프로젝트는 첫 화면 '최근 프로젝트'에서 다시 열 수 있고, 데스크톱 앱은 원본 폴더도 자동으로 다시 연결합니다.
  * 글자가 '…'로 잘려 보이면 마우스를 올리면 전체가 보입니다. 표 머리글에 마우스를 올리면 설명이 나옵니다.
  * 팝업 창은 오른쪽 아래 모서리를 끌어 크기를 바꿀 수 있습니다. 크기는 기억하고, 모서리를 두 번 누르면 원래 크기로 돌아갑니다.
  * [설정]: 왼쪽 칸에서 [분석](제외 규칙·파일 크기)과 [AI 연결] 묶음(AI 공통·Claude·Gemini·ChatGPT, 데스크톱 앱)을 고릅니다.
    [저장]은 바꾼 칸을 모두 저장합니다.
  * 상단의 프로젝트 이름을 누르면 분석했던 프로젝트 목록이 나옵니다. 고르면 그 결과를 바로 엽니다.
    프로젝트 연결(형상관리·DB)은 이름 옆의 연결 아이콘을 누릅니다.


3. AI 연동 (데스크톱 앱, 인터넷 필요) — Claude · Gemini · ChatGPT
--------------------------------------------------------------------
  세 AI 모두 같은 방식으로 일합니다: 계획 모드로 시작 → [수정 진행] → 작업 사본에서 수정 → 변경 검토에서 [적용].
  DB 조회·셸 명령 규칙도 같습니다. 쓰려는 AI만 켜면 됩니다. 상단 [설정] → 왼쪽 [AI 연결] 묶음에서 관리합니다.
  (켠 AI가 없으면 상단 [AI 대화]를 눌러도 기본 AI의 연결 화면이 열립니다)

  [AI 공통]
     - 새 대화의 기본 AI: 켠 AI 중에서 고릅니다. 기본 AI가 꺼지면 켜진 다른 AI로 새 대화를 시작합니다.
     - AI별 차이(연결 방식·인증·요금·보낸 내용 처리)를 한눈에 봅니다.
     - 모든 AI에 같은 권한: 시작 모드·파일 수정·쿼리 규칙과 셸 명령 허용 목록(빌드·테스트 명령, 실행할 때마다 확인).

  [Claude] 준비: 이 PC에 Claude Code가 설치되어 있고 로그인되어 있어야 합니다.
        (명령 프롬프트에서 claude 실행 → /login. 앱은 로그인 정보를 저장하지 않고, 계정 이름만 받아 화면에 보여 줍니다)
     - 인증 방식: Claude Code 로그인 (기본) / API 키 / 회사 클라우드(Bedrock·Google Cloud·Foundry)
     - [다시 확인]으로 CLI·인터넷·인증을 확인하고, 보내는 정보를 읽은 뒤 [연동 켜기].
     - Claude Code를 못 찾으면 [경로 지정]으로 claude.exe를 직접 고릅니다. 회사 프록시는 '사내 프록시' 칸에.
     - 다른 계정으로 바꾸기: [터미널에서 로그인] → 열린 창에 /login 입력 → 브라우저에서 다른 계정으로 로그인
       → 앱에서 [다시 확인]. 이메일이 바뀌면 다음 질문부터 새 계정으로 이어 갑니다. (로그아웃은 같은 창에서 /logout)

  [Gemini] 설치할 것 없음 (앱이 Gemini API에 바로 연결)
     - Gemini API 키: Google AI Studio(aistudio.google.com)에서 키를 만들어 넣습니다.
       결제를 연결하지 않은 무료 키는 보낸 내용이 Google 서비스 개선에 쓰이고 사람이 검토할 수 있습니다.
       회사 소스에는 결제를 연결한 키나 회사 Google Cloud를 쓰세요.
     - 회사 Google Cloud (Vertex AI): 프로젝트 ID·리전만 넣습니다. 인증은 PC의 gcloud 로그인(gcloud auth login)을 그대로 씁니다.
     - Google AI Pro·Ultra 구독 로그인으로는 연결할 수 없습니다(API 사용량은 따로 청구).
     - [연동 켜기]: 지금 값으로 연결을 확인(시험 요청 1번, 요금 없음)한 뒤 켭니다.

  [ChatGPT] 준비: 이 PC에 Codex CLI 0.150.0 이상 (명령 프롬프트에서 npm install -g @openai/codex)
     - ChatGPT 계정 로그인: [터미널에서 로그인] → 열린 창에서 브라우저로 로그인(codex login) → 앱에서 [다시 확인].
       ChatGPT 구독(Plus·Pro·Business 등)의 사용량 안에서 씁니다. 로그아웃은 명령 프롬프트에서 codex logout.
     - OpenAI API 키: OpenAI Platform에서 발급, 쓴 만큼 과금(ChatGPT 구독과 별도). PC의 Codex 로그인은 건드리지 않습니다.
     - 회사 클라우드 (Azure OpenAI): 엔드포인트(https://리소스.openai.azure.com)와 배포 이름. 키를 비우면 PC의 Azure 로그인(az login).
     - Codex를 못 찾으면 [경로 지정]으로 codex.cmd(또는 codex.exe)를 고릅니다.
     - 앱은 Codex 자체 도구(셸·파일 수정·웹 검색)와 PC의 Codex MCP 서버를 끄고 앱 도구만 쓰게 합니다.

  API 키는 Windows 사용자 계정으로 암호화해 저장하고 다시 보여 주지 않습니다. [연동 끄기]는 이 앱에서만 그 AI를 끕니다.

  대화
  1) 화면·테이블·메뉴·배치 상세의 [{기본 AI}에게 묻기](예: [Claude에게 묻기]) 또는 상단 [AI 대화] → 질문을 입력합니다.
     - 처음에는 계획 모드: AI가 소스를 읽고 원인·수정안만 냅니다. 파일은 바꾸지 않습니다.
     - AI는 원본 폴더를 복사한 '작업 사본'에서만 읽고 고칩니다. 접속 정보(비밀번호 등)는 사본에서 가려집니다.
  2) 수정안이 마음에 들면 [수정 진행] → 작업 사본에서 고친 뒤 '작업 사본 변경' 카드가 나옵니다.
  3) [변경 검토]에서 바뀐 줄을 보고 포함할 파일을 고른 뒤 [적용] → 확인 창(적용 후 커밋·커밋 후 푸시 선택)
     → 원본 폴더에 적용하고 바로 다시 분석합니다. 기록은 [이력]에 남습니다. 커밋에는 'Gemini가 작성한 변경'처럼 AI를 적습니다.
  4) 셸 명령(빌드·테스트)은 AI 공통의 허용 목록에 넣은 것만, 실행할 때마다 물어본 뒤 실행합니다.
  5) 새 프로젝트: 첫 화면 [새 프로젝트] → 빈 폴더 선택(AI도 고를 수 있음) → 요구사항 입력 → 계획 확인 → [계획 확정]
     → 생성 → 분석.
  6) AI·모델: 입력란 아래 배지와 모델 이름을 누릅니다.
     - 같은 AI의 다른 모델: 대화가 이어지고 다음 응답부터 그 모델로 답합니다.
     - 다른 AI: 새 대화로 시작합니다. 확인 창에서 '지금 대화를 맥락으로 붙이기'를 켜면 지금 대화의 질문·답변 글이
       「이전 대화 (AI)」 맥락으로 붙습니다(작업 내역·조회 결과는 뺌). 원래 대화는 대화 기록에 그대로 남습니다.
     - 새 대화의 기본 모델은 설정의 각 AI 페이지 '기본 모델'에서 고릅니다.
  7) 대화는 프로젝트마다 따로 저장되고, 대화 기록에 AI 배지(C · G · O)가 붙습니다. 패널 머리 아이콘: 크게 보기 ·
     지금 대화 지우기 · 대화 기록(하나씩 또는 [모두 지우기]) · 내보내기 · 새 대화 · 그 AI의 연결 설정(톱니).
     지워도 작업 사본·작업 이력은 남습니다.
  8) 대화창 너비: 대화창 왼쪽 가장자리를 끌어 넓히거나 줄입니다(기억, 두 번 누르면 원래 너비).
     크게 보기 창은 양옆 가장자리나 오른쪽 아래 모서리를 끌어 크기를 바꿉니다.


4. 형상관리·작업 이력 (데스크톱 앱)
------------------------------------
  - Git·SVN은 폴더의 .git·.svn으로 자동으로 알아봅니다. 상단 프로젝트 이름을 누르면 '프로젝트 연결'에서 확인합니다.
  - 커밋·푸시는 이 PC에 저장된 Git·SVN 로그인을 그대로 씁니다(앱은 계정을 저장하지 않음).
    푸시는 원격 브랜치가 연결된(upstream) 브랜치에서만 됩니다. SVN은 커밋하면 서버에 바로 반영됩니다.
  - [이력]: 코드 적용·되돌리기, 쿼리 실행, 운영 DB 조회 기록. 적용한 변경은 [되돌리기], 기록은 [CSV 내보내기].
    기록은 추가만 되고 지울 수 없습니다.


5. DB 연결 (데스크톱 앱, 사내망)
---------------------------------
  - 상단 프로젝트 이름 → 프로젝트 연결 → [DB 추가]: 개발·QA·운영을 나눠 등록합니다.
    조회 전용 계정(SELECT 권한만)을 함께 넣는 것을 권장합니다. 비밀번호는 Windows 사용자 계정으로 암호화해 저장합니다.
  - AI의 조회: 문장 하나인 SELECT만, 읽기 전용 세션·행 수·시간 제한. 기본 대상은 개발 DB.
    운영 DB 조회는 항상 물어봅니다(끌 수 없음). 개인정보 컬럼은 환경 규칙에 따라 가려서(운영 기본) AI에 보냅니다.
  - SELECT가 아닌 쿼리는 AI가 실행하지 못하고 '변경 쿼리' 카드로 올립니다.
    [실행] → 대상 DB·예상 행 수 확인(운영은 DB 이름 입력) → 트랜잭션 안에서 실행, 행 수가 예상과 다르면 롤백.
  - 메뉴 테이블: 프로젝트 연결 > 메뉴 테이블에서 'DB에서 읽기'를 켜면 분석할 때 메뉴를 DB에서 읽습니다.
  - Oracle 12c 이상은 설치 없이 연결됩니다. 11g는 Oracle Client 19 이상을 설치하고 연결 설정에서 'Thick 모드'를 켭니다.


6. 회사 PC에서 확인이 필요한 것 (이 프로토타입을 만든 환경에서 시험하지 못한 부분)
-----------------------------------------------------------------------------------
  - 실제 Claude 로그인·대화 (시험은 가짜 Claude로 했습니다), Claude Code 경로 자동 찾기
  - 실제 Gemini API 키·회사 Google Cloud(gcloud) 연결 (시험은 가짜 Gemini 서버로 했습니다)
  - 실제 ChatGPT 로그인·OpenAI API 키·Azure OpenAI (Codex 0.150·0.163과의 연동은 가짜 OpenAI 서버로 시험했습니다),
    Windows에서 [터미널에서 로그인]·Codex 경로 자동 찾기(npm 전역 설치 위치)
  - Oracle 조회·쿼리 실행(12c 이상), 11g Thick 모드, MySQL 8의 시간 제한 (MariaDB로는 시험함)
  - Git Credential Manager 로그인 창이 뜨는 푸시, SVN 커밋, 한글이 들어간 폴더 경로
  - 회사 프록시·보안 프로그램 환경에서의 동작
  문제가 생기면 화면의 오류 문구와 함께 알려 주세요.


7. 분석 대상
------------
  - Java·JSP·Spring MVC(전자정부 표준프레임워크 포함)·MyBatis·iBatis
  - PHP(Laravel, CodeIgniter, 프레임워크 없는 PHP), Go(Gin, Echo, net/http 등)
  - Python: Django(urls.py·뷰·템플릿·ORM 모델, DRF API), Flask(Blueprint·Jinja 템플릿·SQLAlchemy),
    FastAPI(APIRouter·SQLAlchemy·SQLModel), DB를 쓰는 Python 배치 스크립트
  - 앱: Android(Java·Kotlin), React Native, Flutter, 하이브리드 WebView — 화면·내비게이션 메뉴·로컬 DB,
    앱이 부르는 API를 같은 폴더의 서버 라우트와 이어 화면별 사용 테이블까지 (앱과 서버는 하위 프로젝트로 나눠 표시)
  - DDL(Oracle·MySQL·MariaDB)의 테이블·컬럼·주석
