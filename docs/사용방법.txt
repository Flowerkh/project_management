프로젝트 분석 시스템 · 프로토타입 v0.4
======================================

프로젝트 폴더를 불러와 [Run]을 누르면, 어떤 시스템인지와
DB 테이블·메뉴·화면·배치의 관계를 정리해 보여 줍니다.
분석은 이 PC 안에서만 하고 인터넷이 없어도 됩니다.
v0.4부터 데스크톱 앱에서 Claude 연동, 형상관리(Git·SVN)·작업 이력, DB 연결을 쓸 수 있습니다.


1. 실행 방법
-------------
[데스크톱 앱]
  1) ProjectAnalyzer-…-win.zip 압축을 풉니다. (설치 필요 없음, 관리자 권한 필요 없음)
  2) 폴더 안의 ProjectAnalyzer.exe 를 실행합니다.
  3) 처음 실행할 때 "Windows의 PC 보호" 창이 뜨면 [추가 정보] → [실행]을 누릅니다.
     (코드 서명을 하지 않은 프로토타입이라 나오는 안내입니다)

[HTML 파일]
  1) project-analyzer.html 을 Edge 또는 Chrome으로 엽니다.
  2) 폴더를 고르면 브라우저가 "파일을 업로드할까요?"라고 묻습니다.
     실제로 업로드되지 않고, 이 브라우저 안에서만 읽습니다. [업로드]를 누르면 됩니다.
  * Claude 연동·형상관리·DB 연결은 데스크톱 앱에서만 됩니다.

[소스에서 실행 (GitHub)]
  Node.js 22 LTS를 설치한 뒤, 저장소 폴더(project_management)에서:
    npm start          ← 패키지 설치(처음이거나 바뀌었을 때만, 처음엔 몇 분) → 빌드 → 실행
    npm run package    ← 실행 파일 zip 만들기 (release\ProjectAnalyzer-…-win.zip, 몇 분 걸림)
  * 새 코드를 받을 때: git pull 뒤 npm start
  * desktop 폴더 안에서 npm start 를 해도 됩니다. node scripts\… 명령은 저장소 폴더에서 실행해야 합니다.


2. 분석 사용 순서
------------------
  1) [폴더 열기]를 누르거나 프로젝트 폴더를 창에 끌어다 놓습니다.
  2) 불러오기 확인 화면에서 분석에서 뺄 폴더를 체크 해제하고 [분석 시작]을 누릅니다.
  3) 결과 요약에서 시스템 유형, 사용 언어·DB, 개수, 확인 필요 항목을 봅니다.
  4) 왼쪽 트리(DB 테이블 / 메뉴 / 화면 / 배치)에서 항목을 누르면 상세가 나옵니다.
  5) 파일 이름을 누르면 소스 보기가 열리고, 근거가 된 줄을 강조해 보여 줍니다.
  6) [결과 파일 저장]으로 결과를 .json 파일로 남길 수 있습니다. (소스 코드는 담지 않습니다)
  * 분석한 프로젝트는 첫 화면 '최근 프로젝트'에서 다시 열 수 있고, 데스크톱 앱은 원본 폴더도 자동으로 다시 연결합니다.


3. Claude 연동 (데스크톱 앱, 인터넷 필요)
------------------------------------------
  준비: 이 PC에 Claude Code가 설치되어 있고 로그인되어 있어야 합니다.
        (명령 프롬프트에서 claude 실행 → /login. 앱은 Claude 계정 정보를 읽거나 저장하지 않습니다)
  1) 상단 [Claude] → Claude 연결 창에서 인증 방식을 고릅니다.
     - Claude Code 로그인 (기본) / API 키 / 회사 클라우드(Bedrock·Google Cloud·Foundry)
     - [다시 확인]으로 CLI·인터넷·인증을 확인하고, 보내는 정보를 읽은 뒤 [연동 켜기].
     - Claude Code를 못 찾으면 [경로 지정]으로 claude.exe를 직접 고릅니다. 회사 프록시는 '사내 프록시' 칸에.
  2) 화면·테이블·메뉴·배치 상세에서 [Claude에게 묻기] → 질문을 입력합니다.
     - 처음에는 계획 모드: Claude가 소스를 읽고 원인·수정안만 냅니다. 파일은 바꾸지 않습니다.
     - Claude는 원본 폴더를 복사한 '작업 사본'에서만 읽고 고칩니다. 접속 정보(비밀번호 등)는 사본에서 가려집니다.
  3) 수정안이 마음에 들면 [수정 진행] → 작업 사본에서 고친 뒤 '작업 사본 변경' 카드가 나옵니다.
  4) [변경 검토]에서 바뀐 줄을 보고 포함할 파일을 고른 뒤 [적용] → 확인 창(적용 후 커밋·커밋 후 푸시 선택)
     → 원본 폴더에 적용하고 바로 다시 분석합니다. 기록은 [이력]에 남습니다.
  5) 셸 명령(빌드·테스트)은 Claude 연결 창의 허용 목록에 넣은 것만, 실행할 때마다 물어본 뒤 실행합니다.
  6) 새 프로젝트: 첫 화면 [새 프로젝트] → 빈 폴더 선택 → 요구사항 입력 → 계획 확인 → [계획 확정]
     → 생성 → 분석.


4. 형상관리·작업 이력 (데스크톱 앱)
------------------------------------
  - Git·SVN은 폴더의 .git·.svn으로 자동으로 알아봅니다. 상단 프로젝트 이름을 누르면 '프로젝트 연결'에서 확인합니다.
  - 커밋·푸시는 이 PC에 저장된 Git·SVN 로그인을 그대로 씁니다(앱은 계정을 저장하지 않음).
    푸시는 원격 브랜치가 연결된(upstream) 브랜치에서만 됩니다. SVN은 커밋하면 서버에 바로 반영됩니다.
  - [이력]: 코드 적용·되돌리기, 쿼리 실행, 운영 DB 조회 기록. 적용한 변경은 [되돌리기], 기록은 [CSV 내보내기].
    기록은 추가만 되고 지울 수 없습니다.


5. DB 연결 (데스크톱 앱, 사내망)
---------------------------------
  - 상단 프로젝트 이름 → 프로젝트 연결 → [DB 추가]: 개발·QA·운영을 나눠 등록합니다.
    조회 전용 계정(SELECT 권한만)을 함께 넣는 것을 권장합니다. 비밀번호는 Windows 사용자 계정으로 암호화해 저장합니다.
  - Claude의 조회: 문장 하나인 SELECT만, 읽기 전용 세션·행 수·시간 제한. 기본 대상은 개발 DB.
    운영 DB 조회는 항상 물어봅니다(끌 수 없음). 개인정보 컬럼은 환경 규칙에 따라 가려서(운영 기본) Claude에 보냅니다.
  - SELECT가 아닌 쿼리는 Claude가 실행하지 못하고 '변경 쿼리' 카드로 올립니다.
    [실행] → 대상 DB·예상 행 수 확인(운영은 DB 이름 입력) → 트랜잭션 안에서 실행, 행 수가 예상과 다르면 롤백.
  - 메뉴 테이블: 프로젝트 연결 > 메뉴 테이블에서 'DB에서 읽기'를 켜면 분석할 때 메뉴를 DB에서 읽습니다.
  - Oracle 12c 이상은 설치 없이 연결됩니다. 11g는 Oracle Client 19 이상을 설치하고 연결 설정에서 'Thick 모드'를 켭니다.


6. 회사 PC에서 확인이 필요한 것 (이 프로토타입을 만든 환경에서 시험하지 못한 부분)
-----------------------------------------------------------------------------------
  - 실제 Claude 로그인·대화 (시험은 가짜 Claude로 했습니다), Claude Code 경로 자동 찾기
  - Oracle 조회·쿼리 실행(12c 이상), 11g Thick 모드, MySQL 8의 시간 제한 (MariaDB로는 시험함)
  - Git Credential Manager 로그인 창이 뜨는 푸시, SVN 커밋, 한글이 들어간 폴더 경로
  - 회사 프록시·보안 프로그램 환경에서의 동작
  문제가 생기면 화면의 오류 문구와 함께 알려 주세요.


7. 분석 대상
------------
  - Java·JSP·Spring MVC(전자정부 표준프레임워크 포함)·MyBatis·iBatis
  - PHP(Laravel, CodeIgniter, 프레임워크 없는 PHP), Go(Gin, Echo, net/http 등)
  - Python: Django(urls.py·뷰·템플릿·ORM 모델, DRF API), Flask(Blueprint·Jinja 템플릿·SQLAlchemy),
    FastAPI(APIRouter·SQLAlchemy·SQLModel), DB를 쓰는 Python 배치 스크립트
  - 앱: Android(Java·Kotlin), React Native, Flutter, 하이브리드 WebView — 화면·내비게이션 메뉴·로컬 DB,
    앱이 부르는 API를 같은 폴더의 서버 라우트와 이어 화면별 사용 테이블까지 (앱과 서버는 하위 프로젝트로 나눠 표시)
  - DDL(Oracle·MySQL·MariaDB)의 테이블·컬럼·주석
  - 메뉴: DB 메뉴 테이블(설정 시), 메뉴 데이터 SQL(INSERT), 메뉴 설정 파일, 사이드 메뉴 화면 코드, 앱 내비게이션, 없으면 URL로 추정
  - 배치: 셸·배치·PowerShell·Python 스크립트, crontab, 작업 스케줄러 내보내기(XML), @Scheduled
  - React Native·Flutter 프로젝트의 ios 폴더는 기본으로 뺍니다(iOS 네이티브는 대상 아님).
  - 소스 보기에서 DB 접속 정보(주소·계정·비밀번호)는 ****로 가려 보여 줍니다.

9. 결과 읽는 법
----------------
  - [추정]: 직접 근거가 없거나 동적 SQL이라 규칙으로 유추한 결과입니다.
  - 신뢰도(높음·보통·낮음): 결과가 맞을 가능성입니다.
  - 확인 필요: 화면과 연결되지 않은 테이블, 메뉴에 없는 화면, 실행 주기를 못 찾은 배치,
    처리 메서드를 못 찾은 URL, DB 메뉴와 소스 메뉴가 다른 곳 등 사람이 확인해야 할 것을 모아 둡니다.
